<Section eyebrow="Context" title="Why this exists">

I teach guitar, and I practice with this page myself. It has widened my own chord vocabulary, which is the best argument I have for it.

Fretboard Lab puts the neck, the key and a timeline on one page. Pick an instrument and a tuning, pick a key, and build sixteen bars across four lanes — chords on one, lead lines on the others. It plays back, loops, slows down for practice, suggests what could come next and why, and exports MIDI so a sketch can carry on in a DAW. I take mine into BandLab.

It is built on <a href="https://github.com/tonaljs/tonal" target="_blank" rel="noreferrer" className="underline decoration-[color:var(--muted)] underline-offset-4 transition hover:text-[color:var(--accent)]">tonal</a>, danigb's open-source music theory library (MIT). The theory of notes, chords and keys is tonal's. Everything about necks, hands, timelines and sound is new.

</Section>

<Decisions items={[
  {
    title: "Extend the library instead of writing around it",
    body: "The new code lives in five packages beside tonal's own — tuning, fretboard, chord-shape, harmony and timeline — each with its own tests and README. The page only draws what they compute. More ceremony per feature, but every rule about a neck or a bar can be tested without opening a browser.",
  },
  {
    title: "Chord shapes from rules, not a lookup table",
    body: "Give it a chord name and it works out every way a hand can play it on the strings in front of it, ordered the way shapes are taught. Because nothing is hard-coded to standard guitar tuning, the same code answers for a different tuning, a capo, or another instrument: bass, ukulele, banjo, and cello (which has no frets, so it gets positions instead).",
  },
  {
    title: "One timeline for the screen, the speakers and the file",
    body: "The timeline knows its tempo, so it can say when every note sounds, in seconds. Playback and MIDI export both read that same answer, and mute and solo apply to both — the file holds what you hear.",
  },
  {
    title: "No build step for the page",
    body: "The page is plain ES modules and one HTML file. Publishing it means copying files, so the hosted build installs nothing and there is no bundler to break between me and a friend opening a link.",
  },
  {
    title: "Assume the browser might say no",
    body: "Storage can be blocked, and a page inside a frame gets no prompt, no confirm and sometimes no downloads. So saving falls back to memory, questions are asked in the page itself, and files go out by whichever route the host allows. That is why the demo above can run inside this page.",
  },
]} />

</Section>
